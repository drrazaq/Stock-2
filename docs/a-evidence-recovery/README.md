## Recovery integrity and failure handling

Original locks are opaque; age or a missing guessed PID is never permission to delete them. Every attempt uses a fresh exclusive directory. `original/` retains source bytes including lock and damaged tail. `secondary/` contains only a reconstructed view. `RECOVERY_STARTED.json` records original hashes and non-authority; only `RECOVERY_COMPLETE.json` certifies structural secondary completion. A failed/interrupted attempt remains incomplete and is never automatically cleaned up or reused. Retry uses a different destination. The reconstructed manifest carries a secondary-only marker: the unchanged store's exact-manifest check refuses reopening this copy as a normal writer. This fence is verified at all eight original interruption boundaries. Original complete outcomes cannot be replaced; real SIGKILL tests preserve losing outcomes exactly once. A copy cannot recover bytes never persisted, repair mid-chain corruption, authenticate past observations or establish a primary writer's quiescence.
