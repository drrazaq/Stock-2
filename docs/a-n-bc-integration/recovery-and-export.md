# Inactive recovery and legacy preservation procedure

No procedure text authorizes real recovery, new authority, setup, migration or collection. Use only an independently approved source/code/contract/cohort and authority. Public test roots are refused for retained stores; synthetic exceptions remain explicit.

## Same-import interruption (N1)

1. Preserve the exact request, original directory, native archives, old store and signed-source custody. Never delete a lock or partial file. Stop concurrent operators and inspect HEAD, pending intent and unclassified fragment counts. A stale token is not recovery authority.
2. Repeat `importNativeAEvidence` with the **same pinned request and originals**. The importer scopes its intents by request hash and repairs them under the same fenced token and kernel lock before continuing. The intent contains the exact body required to finish an interrupted original append. Completed earlier records may be read/repeated idempotently while the later scoped intent is repaired. Evaluation is recomputed against the exact stored originals, never supplied as an arbitrary result.
3. A pending pre-revision original can be matched only by its exact logical ID/source-file/hash tuple; a legacy evaluation additionally requires the same original dataset/contract and the identical recomputed result. An immutable `legacy-import-replay-<intentHash>.json` binds the existing file, intent/record hashes, scope, token and bytes before completion. Retry after this receipt is idempotent. Original intent/record/raw/control bytes are not rewritten.
4. Foreign scope, ambiguous derived legacy work, conflicting raw bodies, changed committed originals, unclassified fragments or insufficient capacity: return UNKNOWN/REVIEW_REQUIRED, preserve everything and stop. These statuses do **not** prove the source was genuinely missing. An operator may inspect/export; do not guess a derived body or clear a transaction. A genuinely unavailable original remains unresolved and requires the separately reviewed signed unresolved transition, never an automatic disposal. That transition permanently preserves missingness and cannot create a successful admission.
5. Verify exact old bytes plus one logical commit per operation, current generation, no remaining pending work, saved report and UNKNOWN propagation. Any missing report is not success.16MiB total/2000files/15sec worker remain fixed; scoped inline replay counts against capacity and is preflighted before intent creation.

SIGKILL tests cover canonical durable publication boundaries, including original, record, commit and legacy replay receipt. They do not establish physical disk/power guarantees or automatically reconcile an arbitrary torn temporary file. Such fragments block positive evaluation, remain intact and require reviewed reconciliation.

## Invalid standalone reservation quarantine (N3)

1. `inspectRequest(filename)` is read-only and can describe malformed JSON. Pin exact bytes/hash, HEAD, store/cohort/contract and independent boundary evidence. Do not publish private source bytes.
2. An explicitly authorized operator obtains a **new**, independently signed `QUARANTINE_INVALID_REQUEST` authorization from the enrolled recovery authority through the existing private0600 single-link source channel. Body fields are fixed in `quarantineBody`: schema/action/storeId/cohortHash/contractHash/expectedHeadHash/reason/requestFile/requestSha256/boundaryEvidenceHash/at. Reason is only UNVERIFIABLE_UNREFERENCED_RESERVATION. Old writer token cannot sign or authorize it.
3. Call `quarantineRequest({authorizationSource})`. Under lock and current-head comparison, the worker rejects any referenced attempt or valid signed reservation. It durably preserves exact authorization bytes, an immutable byte copy and a signed receipt. Tests interrupt after each publication and verify exact retry. Original request stays in place. A later changed version needs a new signed decision and separately preserved copy.
4. Verify source/copy/receipt hashes and unchanged HEAD. Discovery may exclude only the exact quarantined hash. `resumeClaim` refuses that request: quarantine permits **no takeover**. A separate valid signed claim remains necessary. If authority or validity is unknown, stop rather than retire it.

## Legacy rootless read-only path (N4)

`planLegacyCopyOut(store)` uses `exportSnapshot()` under the permanent kernel lock opened read-only. Verify manifest, all filenames/bytes/hash references, source HEAD and pending/control/outcome files. No head reset, authority enrollment, outcome replay or data deletion occurs. Unknowns remain unknown.

The inactive CLI `node tools/a-legacy-store-export.mjs <source>` performs inspection only; it has no mutation or copy-out flags. The separate library call `writeLegacyCopyOut({snapshot,outputDirectory,filename,expectedManifestHash})` requires an explicit exact snapshot and separate private migration authorization for a real store. Destination must be existing private0700, regular new0600 file, no links/replacement; full output is read back. Original16MiB/2000-file caps remain; base64 envelope has a separate32MiB serialization cap. Partial destination artifacts are retained on interruption, not silently overwritten. Check exact full hash before using a completed copy. This is plaintext private copy-out; encrypted custody must be separately approved and established before real export. Do not copy real records into repository, public artifacts or logs.

`prepareLegacyMigration` is a **plan only** for labelled unverified legacy context. It neither creates a target nor replays/admits old evaluations. New target enrollment, ciphertext custody, reconciliation and any financial/private migration remain separate owner decisions. The new code itself is awaiting focused independent review.
