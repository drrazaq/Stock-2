## Publication and observation contract

The watcher confirms a remote reservation **before** invoking transport. `watcher-message-publish.mjs` fetches the current upstream into a private ref, builds a one-path commit using an isolated temporary Git index and the latest remote parent, then attempts a normal fast-forward push. It retries racing pushes within **three attempts and a4-second publication budget**, with at most1second cleanup. It neither moves active HEAD/index nor checks out, pulls or rebases active source. Unrelated remote changes survive. Existing checkout credentials and contents permission are used; no new credential or permission is configured.

A competing owner cannot obtain the same reserved key. An uncertain push is resolved by a bounded fetch/owner comparison; absence of confirmed permission means no send. Malformed/legacy reservation records are quarantined rather than treated as empty. The run continues if Git publication fails. Stop warnings known unsent can be retried; radar delivery retries the already frozen snapshot rather than repeating catalyst/SEC collection or changing enrollment. Per-key retry cooldown is60seconds. Other caller-specific research delivery windows remain in force; stale leads are not replayed merely to increase delivery counts.

| State | Meaning | Retry rule |
|---|---|---|
| UNSENT | No transport attempted, publication unconfirmed, or explicit pre-delivery rejection | Bounded later claim may retry; failure alone does not consume the key |
| RESERVED | Remote permission confirmed; outcome not yet durably classified | Other owners do not send; crash/uncertainty requires reconciliation |
| ACKNOWLEDGED | Actual Telegram JSON acknowledgement received | Suppress repeats |
| UNCERTAIN | Request may have reached Telegram; no definitive acknowledgement | Suppress automatic resend; review independently |

A failed outcome-publication can leave remote RESERVED while a local acknowledgement exists. That is conservative uncertainty, not a fresh permission. Midday child-process exit is not delivery proof: the actual radar transport returns explicit per-message acknowledgement/rejection evidence to its parent, including partial multi-part uncertainty. Known-unsent new state takes precedence over legacy radar-list records, which alone are not acknowledgement proof.

Local state lives under `runtime/watcher-message-state`; it is not staged over concurrent remote reservation changes. The isolated publisher owns the protected public state path. Each completed observation cycle atomically replaces a per-run progress snapshot; normal completion also preserves the original final/shadow archive. Progress contains completed beats only. An in-flight minute is not invented as observed. The proposed workflow retains run/progress/runtime-state artifacts on success or failure for7days, including final publication conflicts. This workflow is an inactive patch, not installed/dispatched. Runner destruction can still lose unuploaded bytes; missing evidence remains UNKNOWN.
