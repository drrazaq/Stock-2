# Acceptance ordering decision — inactive, unchanged V1

Observed production source: SEC hotfix `bd70f5a76172f369e9dff1096eba0e526c0e3fdc`; offline baseline `5dc6cc769e7cff0d5cf1bf2501e1d32f2e55298f`. No producer order or frozen evaluator is changed by this analysis.

The minute loop receives market snapshots, evaluates ignition/early-wave candidates (some existing paths can request issuer submissions), then calls `pollEdgar`, then `decideFilings`. `pollEdgar` first loads the ticker map if needed, pages Atom 8-K and 6-K responses, records first observation, and queues filings. `decideFilings` can request submissions only after cheap D checks, a usable price and the minute/call limits permit. Some filings never cause a submissions request. Atom `updated` is not authenticated acceptance. The native tee adds no source request.

V1 requires original observation within the fixed 09:30–09:34 enrollment window, verified acceptance available with that first observation, complete identity/ZAD evidence and timely pre-quote handoff. If a proof arrives after first observation, it remains a late supplement even on restart; original clocks cannot be repaired. A quote already taken after detection cannot become a retrospective entry.

Consequently, the normal Atom-first → submissions-later path cannot enroll in unchanged V1. The colocated host fixes transport latency, not this ordering constraint. A previous existing same-issuer safety check may already contain the accession before the first Atom observation; that conditional path can supply timely proof. It is not guaranteed, is not triggered for every six-name event and has no measured frequency. Earlier archived observations before enrollment start do not become new signals. Unknown transport/authenticity, failed proof, revised/conflicting evidence and missing lineage remain unresolved. V1 feasibility is NOT ESTABLISHED; zero eligible events is valid.

Smallest explicit alternative: a separately reviewed V2 cohort whose eligibility clock is the first persisted moment when both the original event and its matching existing submissions proof are available. Preserve original acceptance/ingestion/observation clocks; add `eligibilityEstablishedAt`, require this clock within the enrollment window, and enter only at the next fresh executable quote after that clock and handoff. Run the same 30-minute exit horizon from that actual entry, with unchanged costs, capacity, controls and followups. Record discovery-to-proof latency and pre-eligibility price movement. This changes the enrollment hypothesis and cohort, not historical clocks; V1 results cannot be pooled or called confirmation of V2. No extra provider calls or producer reordering is needed, but zero proofs remains possible. The alternative is prepared as an unapproved specification only, not implemented in the frozen evaluator.

Other alternatives—prefetching filings, additional submissions requests or changing producer call order—need separate request-scope/behavior review. The existing 18-reference + 41-capture = 59 additional-source-request maximum is unchanged. Completing plumbing alone does not authorize collection or establish admission readiness. The six-name operational calibration is not the broader intraday/days/weeks/months trading-mentor evaluation.
