# Private quote retention — development only

Base d2852739. No workflow/settings/credential changes and no live data collected. Stage 1/2/113 source scopes are unchanged. This is an opt-in bounded producer plus atomic pointer consumer, not a production deployment or demonstrated market coverage.

## Actual caller chain

`ignition-watch.mjs` may explicitly construct `createPrivateQuoteRetention` only when PRIVATE_QUOTE_RETENTION_ROOT and PRIVATE_QUOTE_POLICY_SHA256 are supplied externally. The directory must already exist, be owner-private (0700), outside the checkout, with an independently reviewed/pinned policy.json and hashed identities.json. No file/secret/config is provisioned automatically. Source SHA must equal the policy's reviewed producer. An absent opt-in makes the existing watcher snapshot calls with a null callback and leaves retention off.

`alpaca-feed.mjs::snapshots` calls the optional observer once per actual transport result, before normal watcher normalization/merging, including SIP403 then IEX success, failures and invalid JSON. Receipt time is after body decoding and schema validation, not provider time or an inferred receipt reconstructed later. Callback gets a structured clone, no headers/URL/key; it cannot mutate the caller's trading payload. Observer failure records only a generic diagnostic and never causes another provider request or changes the returned price payload. The existing fallback policy is unchanged. No new endpoint/feed/symbol acquisition or scheduling is introduced.

Provider time, ingestion receipt and request-start are distinct. The quote retains securityId, issuer CIK, NY provider/receipt session, source/feed, bid/ask, nullable native/displayed sizes, conditions, as-observed basis and explicit expiry. Missing or future provider time is never replaced by receipt or trade time. Reviewed identity mapping is still required by the original assessment reader; ticker-only or type-only data cannot authorize a quote join. The external policy/identity review is a real activation prerequisite; synthetic review URLs are fixtures only.

**Current Alpaca sizes are shares, not 100-share lots.** Official schema says shares since November 3, 2025: https://docs.alpaca.markets/us/reference/stocklatestquotesingle-1 and official schema https://github.com/alpacahq/cli/blob/main/api/specs/market-data-api.json . The producer preserves native integers unchanged for current data. Older unit semantics remain UNKNOWN, not automatically multiplied. Displayed size is never fill capacity. IEX is that feed's quote, not a consolidated SIP claim.

## Publication, bounds and failure

One fresh private run root and exclusive directory lock. Each generation writes immutable gzip + hash-bound manifest; then current.json is atomically renamed and fsynced. The current manifest's quotes are the latest observations per symbol (equal-receipt conflicts are retained); all earlier attempts/observations also remain in each archive. A later missing quote replaces the current observation with missing fields, not an old good quote. Reader opens one immutable generation, checks policy pin and manifest hash, then calls the already-reviewed readAssessmentQuote/joinAssessmentQuote. It rechecks all original issuer/session/120-second age rules at reading time. An expired pointer is UNKNOWN. Recovery never refreshes it.

At most 30,000 observations, eight generations, 4 MiB compressed/archive, 16 MiB expanded/archive, and 32 MiB total stored run files, including older generations and identity/policy. Storage is conservative: all generations duplicate previous observations. This prototype is finite and **does not promise full-session retention**; a batch-rich watcher can hit eight publications quickly. At cap/failure it stops recording, invalidates current pointer and keeps previous evidence. No automatic rotation, deletion, restart, lock takeover or quota increase. Any partial write or stale lock needs explicit read-only diagnosis; an interrupted publication may leave the previous pointer valid only until its original expiry. A crash before durable publication yields no complete-generation claim. Files under private root are 0600; lock/root 0700. No raw fields are printed, pushed, artifacted or put in public data paths.

`ASSESSMENT_PRIVATE_QUOTE_ROOT` plus pinned `ASSESSMENT_PRIVATE_QUOTE_POLICY_SHA256` is the development assessment opt-in. Missing policy, unreadable/hash mismatch/invalid pointer yields UNKNOWN; no fallback to a less strict static archive after an explicitly configured private-pointer failure. The public source contains only synthetic test data. Runtime policy review, host/private path permissions, publication transport between separate jobs and retention/location require a separate exact activation package. In-process/same-host fixtures prove a working boundary, not inter-runner availability or production custody.

## Recovery

After writer close, offline export returns a bounded hash-pinned recovery envelope (at most 48 MiB); it does not upload it. Separate empty private directory restore checks every allowed filename/hash before writing. Original provider/receipt/session/expiry/policy bytes are identical. An externally retained bundle hash is required; hashes prove integrity, not independent provenance. Unknown files/active writer/nonempty target/tampered bundle fail. No production cleanup or Git retention is implied. Owner-held off-runner custody must be separately approved before real data activation.

## Validation

Synthetic actual snapshots → producer → private pointer → actual assessmentContext passes; adverse future/stale/missing/cross-session/identity cases, fallback attribution, partial size/conditions, generation cap, exclusive writer, immutable generations, expiry, failed transport and byte-preserving recovery are tested. Full validation and independent Claude verdict are reported separately. Economic findings are not inferred from software tests.
