# Private quote retention — development only

Base d2852739. No workflow/settings/credential changes and no live data collected. Stage 1/2/113 source scopes are unchanged. This is an opt-in bounded producer plus atomic pointer consumer, not a production deployment or demonstrated market coverage.

## Actual caller chain

`ignition-watch.mjs` may explicitly construct `createPrivateQuoteRetention` only when PRIVATE_QUOTE_RETENTION_ROOT and PRIVATE_QUOTE_POLICY_SHA256 are supplied externally. The base directory must already exist, be owner-private (0700), outside the checkout, with an independently reviewed/pinned policy.json and hashed identities.json. No file/secret/config is provisioned automatically. Source SHA must equal the policy's reviewed producer. Each actual run creates a fresh root/runId subdirectory with a byte-identical policy and identity copy. Bad pins, reused run IDs or stale locks disable only recording and emit a visible generic diagnostic; they do not take down the watcher. Old roots/locks are not stolen or deleted. An absent opt-in makes the existing watcher snapshot calls with a null callback and leaves retention off.

`alpaca-feed.mjs::snapshots` calls the optional observer once per actual transport result, before normal watcher normalization/merging, including SIP403 then IEX success, failures and invalid JSON. Receipt time is after body decoding and schema validation, not provider time or an inferred receipt reconstructed later. Callback gets a structured clone, no headers/URL/key; it cannot mutate the caller's trading payload. Observer failure records only a generic diagnostic and never causes another provider request or changes the returned price payload. The existing fallback policy is unchanged. No new endpoint/feed/symbol acquisition or scheduling is introduced.

Provider time, ingestion receipt and request-start are distinct. The quote retains securityId, issuer CIK, NY provider/receipt session, source/feed, bid/ask, nullable native/displayed sizes, conditions, as-observed basis and explicit expiry. Missing or future provider time is never replaced by receipt or trade time. Reviewed identity mapping is still required by the original assessment reader; ticker-only or type-only data cannot authorize a quote join. The external policy/identity review is a real activation prerequisite; synthetic review URLs are fixtures only.

**Current Alpaca sizes are shares, not 100-share lots.** Official schema says shares since November 3, 2025: https://docs.alpaca.markets/us/reference/stocklatestquotesingle-1 and official schema https://github.com/alpacahq/cli/blob/main/api/specs/market-data-api.json . The producer preserves native integers unchanged for current data. Older unit semantics remain UNKNOWN, not automatically multiplied. Displayed size is never fill capacity. IEX is that feed's quote, not a consolidated SIP claim.

## Publication, bounds and failure

One fresh private run root and exclusive directory lock. Every transport result appends a bounded whitelisted receipt/quote record to fsynced receipts.jsonl BEFORE watcher normalization. At the end of each actual watcher cycle, immutable gzip + hash-bound manifest are published and current.json is atomically renamed and fsynced. The current manifest contains latest observations per symbol (equal-receipt successful conflicts retained), while all earlier attempts/observations remain in the append-only journal. A transport failure marks only its requested symbols unknown; valid quotes from other parts remain usable within their original age limit. A later missing quote replaces the current observation with missing fields, not an old good quote. Reader opens one immutable generation, checks policy pin and manifest hash, then calls the already-reviewed readAssessmentQuote/joinAssessmentQuote. It rechecks all original issuer/session/120-second age rules at reading time. An expired pointer is UNKNOWN. Recovery never refreshes it.

At most 30,000 observations, eight generations, 4 MiB compressed/archive, 16 MiB expanded/archive, and 32 MiB total stored run files, including older generations and identity/policy. At most 30,000 transport attempts too. Current snapshots duplicate latest-per-symbol context, not the whole history; history is append-only. Generations are CYCLES, not individual 200-symbol transport parts. This bounded prototype **does not promise full-session retention**: a 6,600-symbol cycle uses 6,600 observation slots, allowing four complete cycles before the 30,000-row cap stops a fifth. Eight smaller cycles is the other limit; byte limits can stop sooner. No limit was increased to manufacture full-session coverage. At storage/publication/cap failure it stops recording, invalidates current pointer and keeps previous evidence. No automatic rotation, deletion, restart, lock takeover or quota increase. Any partial write or stale lock needs explicit read-only diagnosis; an interrupted publication may leave the previous pointer valid only until its original expiry. A crash before durable publication yields no complete-generation claim. Initialization and per-cycle retention status/observation/attempt/generation counts appear in watcher logs and progress/final health evidence, only when opted in. These contain no quote values, keys, identities or private paths. Recording-disabled/STOPPED is visible, not silently inferred from an unread feed diagnostic. Files under private root are 0600; lock/root 0700. No raw fields are printed, pushed, artifacted or put in public data paths.

`ASSESSMENT_PRIVATE_QUOTE_ROOT` plus pinned `ASSESSMENT_PRIVATE_QUOTE_POLICY_SHA256` is the development assessment opt-in. Missing policy, unreadable/hash mismatch/invalid pointer yields UNKNOWN; no fallback to a less strict static archive after an explicitly configured private-pointer failure. The public source contains only synthetic test data. Runtime policy review, host/private path permissions, publication transport between separate jobs and retention/location require a separate exact activation package. In-process/same-host fixtures prove a working boundary, not inter-runner availability or production custody.

## Recovery

After writer close, offline export returns a bounded hash-pinned recovery envelope (at most 48 MiB); it does not upload it. Separate empty private directory restore checks every allowed filename/hash before writing. Original provider/receipt/session/expiry/policy bytes are identical. An externally retained bundle hash is required; hashes prove integrity, not independent provenance. Unknown files/active writer/nonempty target/tampered bundle fail. No production cleanup or Git retention is implied. Owner-held off-runner custody must be separately approved before real data activation.

Full validation and independent Claude verdict are reported separately. Economic findings are not inferred from software tests.

## Measured overhead and fresh-at-fetch safeguard

The reproducible offline benchmark uses 132 synthetic 200-symbol transport parts, 26,400 observations and four publications. Local median receipt-journal overhead36.1ms, p95 81.5ms, max120.8ms; cycle publication32.6–53.8ms;14,059,936 private bytes. These are one local filesystem measurement, not a hosted guarantee. The original body-receipt clock is captured before observer work. With recording ON the watcher validates provider trade/quote clocks against that original receipt, not the later return time: the adverse fixture advances one second in the observer and still rejects a quote/trade future by0.5second at receipt. OFF keeps the prior watcher timing path. A separate host rehearsal/latency measurement remains mandatory before activation.
