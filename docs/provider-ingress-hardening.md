# Provider ingress hardening — development only

Alpaca snapshot transport now accepts only the official data API origin or explicit localhost fixtures, with no userinfo/path/query/fragment base overrides. GET and redirect refusal override caller preferences; APCA credential headers cannot be forwarded by an automatic redirect to a different service. Requested symbols must already be canonical accepted syntax; class punctuation is never guessed or conflated, and null/empty/ambiguous scopes are refused before transport. This is internal input policy, not an inferred account/plan limit.

Request evidence counts attempts before transport, including failed network requests. HTTP refusals, rate-limit cooldowns and per-response SIP/IEX provenance remain explicit. A successful status alone cannot turn error-shaped or unsolicited symbol records into an observed valid snapshot. Empty/missing symbol data still proves no fresh coverage. SIP403 can cause the existing explicit IEX downgrade;422/429 do not imply subscription entitlement. Tests use synthetic responses and do not establish account plan or upgraded service.

Provider diagnostic age percentiles exclude future clocks while recording their count; future prices never improve freshness. Four regressions cover forced read-only/redirect behavior and failed-attempt counts, credential-destination/symbol rejection, malformed successful payloads and future-clock age separation. Existing localhost watcher/premarket integration remains in the full suite. No live probe, purchase, secret change or production deployment was performed. Full provider entitlement, symbol/session normalization and actual complete-session latency/coverage acceptance remain open.
