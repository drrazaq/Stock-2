## What this proves, and what it cannot

Existing job success, a final save commit and equal final local/remote state cannot prove that a save/rebase preserved the state the child intended to save. A save can discard an intended position change, retain a newer Telegram offset, commit successfully and leave a clean checkout. That concrete synthetic failure is reproduced and refused here. Neither a current repository snapshot nor a new process can reconstruct an earlier process's missing pre-save witness. No claim is made that queued commands have been processed or preserved.

The callable `ReceiptSession` observer starts **before the first child invocation**, observes each existing child/save cycle, records protected file byte identities and the offset internally immediately before save, and verifies the intended bytes against the post-save index, checkout and commit. A failure stays latched. An interrupted or overlapping cycle cannot yield PASS. At finalization, confirmed commits must remain ancestors, all local `data/` files must be saved, protected remote state and pinned source must match, and local/remote HEADs are revalidated. Unrelated remote data changes are allowed; there is no pull, rebase, reset, recovery or push by the observer. Source changes followed by reversion remain detectable in the observed commit interval.

**PASS means only that the cycles witnessed by this trusted original process were persisted.** It is not proof of workflow quiescence, Telegram delivery/queue contents, valid financial semantics, authenticated initial historical state, or commands the bot never received. It does not establish atomic exclusion against a later writer. No private values, offsets, record identifiers, file fingerprints or provider text are emitted. The receipt contains only operational run/commit metadata. Such metadata is not self-authenticating: a future reviewed original-run host and retained job artifact must bind its provenance. A CLI started after an old bot finishes is not a substitute.

The observer performs read-only access to existing local state and Git objects; it does not decrypt, modify financial records or change Telegram offsets. Only its separate, private output directory is written. Actual save callbacks retain their existing behavior; the observer does not repair failed transactions. Genuinely absent optional ledgers are not manufactured, but this is **not** an exemption from the separate accounting-history checks. Privacy-mode drift, previously present missing state, malformed/missing offsets, symlinks, unreadable files and uncertain ancestry refuse proof.

Bounds: 4,096 witnessed cycles/commits, 1,024 commits per final ancestry interval, 128 protected/source paths, 8,192 data files, 128 MiB/file, 1 GiB per data pass, 8 MiB per Git output and 5 seconds/Git operation. Finalization has a cooperative 45-second bound; the shipped one-shot wrapper has a hard 60-second limit. The future long-running original host must supply its own bounded finalization supervisor; running that wrapper as a later process would lose the witness. Git lazy fetching is disabled and the protocol is forbidden. Blob-filtered metadata tests remove protected blobs and prove no implicit network acquisition.

GitHub client: at most 16 GETs, 10 seconds/request, 45 seconds total, 4 MiB/response, 24 MiB total. Complete non-truncated object metadata and verified ancestry are required. No protected remote blob body is fetched. A moved remote, malformed response, rate limit, request exhaustion or unavailable state cannot establish the receipt. The fixed allowance is a ceiling, not a promise that every tree layout fits; exhaustion is an explicit failure.

Publication uses an exclusive 0600 temporary file outside the checkout, file fsync, atomic no-overwrite hard link, inode checks and directory fsync. Competing processes publish at most one receipt. Failure before linking leaves no final receipt and permits a clean retry. Failure after linking/directory fsync may leave an unacknowledged artifact: **the artifact alone is not PASS**, must not be auto-consumed or overwritten, and needs separately reviewed reconciliation. No interrupted witness recovery is claimed.
