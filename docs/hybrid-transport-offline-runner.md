# Bounded transport and offline-only runner

hybrid-snapshot-transport.mjs has no default fetch and reads no environment keys. An explicit caller supplies a fetcher/credentials; only GET snapshots on official Alpaca data origin (or localhost fixture) with canonical explicit symbols and an explicit SIP/IEX feed are permitted. No orders, retries, fallback or activation. State tracks attempts before fetch, actual streamed bytes, minute pacing, duration, timeout and cancellation.401/403/429 halt globally. Pacing returns PACED rather than hiding a retry. Byte checks bound admitted response data, not total TCP buffers or process RSS; JSON parsing still needs memory proportional to the bounded body.

The CLI only accepts --fixture INPUT NEW_OUTPUT_DIR, refuses live/default modes and existing output, and never reads existing provider/encryption secrets. Its transport is an injected local response simulator, even when provider keys exist in the environment. Reports are labelled OFFLINE_HYBRID_FIXTURE_ONLY; no upload workflow is added.330-minute end-to-end fixture joins bounded calls, explicit universe, source adapters, original detection and observed crossings, with missing feed/stale quote/duplicate/cancelled cases remaining incomplete.

Ten transport tests plus three runner tests and seven session-admission tests pass locally. Secret-free research CI and full push/PR/safety are required on published source. This infrastructure is not authorization, actual universe coverage, live collection, executable fills or a profitable strategy. The old Phase A source/workflow and420-request limit are not changed or relabelled. New live collector/recovery/pinned wrapper still requires separate dated review/approval.
